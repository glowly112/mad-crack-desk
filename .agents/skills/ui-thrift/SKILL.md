# UI thrift

Hard default for every UI ask. Loading means reading this skill and stamping the process before any pixels. Naming the skill in prose is not a load.

Does not replace [One UI factory](sand-workflow:one-ui-factory). Factory is the line. This is the load gate. On iOS, also load [iOS 26](sand-workflow:ios-26).

Charm lives here. Chrome on iOS lives in [iOS 26](sand-workflow:ios-26). Both have to pass.

## When

UI, UX, design, layout, prototype, app shell, redesign, “look like X”, Mobbin, polish, visual screen. Detect and load. Do not wait for `/ui-thrift`.

Escalate-only (not the load path): ui-craft, ui-bp, ui-design, ui-app, ui-team. Those fire after two thrift fails or an explicit ask.

## Load then process

Before any layout or CSS or custom SwiftUI chrome:

1. Classify as UI work
2. Read this skill and [One UI factory](sand-workflow:one-ui-factory). If iOS, read [iOS 26](sand-workflow:ios-26)
3. Ban list in working memory
4. Visual product? Lock 3–5 shipped refs ([Brief to references](sand-workflow:brief-to-references)). Skip only for typo / copy-only / no pixels. Keepers are screens of the job’s surface, not a neighbouring genre
5. Stamp SUBJECT / JOB / SIGN / SKELETON / ANTI / REFUSE
6. Implement only after that stamp
7. Self-check. Fail-closed

Do not print `load:` yaml in the user chat. A stamp without those Reads is not a load.

## Ban (fail if shipped)

- Three or more equal bordered cards as the *chrome* (a generic card wall). Product surfaces as *content* can stay if they were in the keepers
- Emoji as nav or icons
- Fake glass: custom `backdrop-filter` / home-rolled blur chrome. iOS 26 system Liquid Glass on stock controls is required, not banned
- Coverage or status pill farms
- Same radius and padding on every block when that is not the keeper
- Inter / Roboto / IBM Plex / SF as the product face when a named face was in scope
- Default Palatino / Georgia / “warm serif on cream” when no named face was locked
- Invented chrome with no keeper URL when refs applied
- Drawing the job’s metaphor in CSS (a shopfront, loaves, a scene) instead of a usable page. Look is the feel of the page
- **iOS:** a correct system toolbar that dropped the product’s type, colour, greeting, or voice
- Generated sample or empty copy (poetic journal, stacked dates as a second headline, typeface chips). Empty is **Empty**. Date is quiet meta.
- Home subtitle or section headers as SF caption or a frozen bitmap. Live product marks in stock slots. Large title stays type.
- Near-vertical texture that reads as pinstripe. Grain speckle can stay. Ruled paper is horizontal. Background tooth must be **readable** on light and dark — a flat wall is a miss, pinstripe is a miss.
- iOS dark mode as system gray Notes. Product night. Product surfaces keep their fills. Chrome follows the appearance picker this tap.
- Ink **on** a light product surface uses that surface’s ink. Never `Color.primary` that flips to cream-on-cream in Dark.
- Cream-on-cream chrome: Dark buttons with no contrast. Light: ink fill, cream label. Dark: contrasting fill, cream label.
- SF glyphs where official third-party app icons exist. Copy is **Import**, not Bring in. No OAuth / live sync invented for those.
- Welcome Mesh / name-capture / paywall / a bigger logo / blank frames. Opening is a product event (surface arrives, then the mark lands), then lessons that show the product in use. No app name unless they asked. No rejected metaphor copy.
- Settings without Appearance (System / Light / Dark) when they asked for it, or Settings chrome that ignores Dark. Connections without official app marks, or copy that still says Bring in.
